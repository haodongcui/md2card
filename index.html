THE DETAILS THAT MATTER

难处理的部分，也应该有明确的处理方式

Md2Card 不把“导入、分页、导出”当成黑箱。下面是它为技术 Markdown 做出的具体取舍。

01 / 本地图片

按文章实际引用定位图片，不把整个文件夹搬进来

导入 .md 后会识别 ![说明](assets/figure.png) 这样的相对路径。选择文章根目录或 assets 文件夹后，先建立目录索引，再只读取当前文章需要的候选图片。

  • 完整相对路径优先，支持 ./ 与 ../
  • 同名图片存在歧义时保留“路径冲突”，绝不随机误绑
  • 图片管理器可手动替换、绑定与清理；Markdown 正文不会被改写
02 / 自动分页

不是按字数硬切

页面根据真实 DOM 高度测量。标题会带着必要的上下文移动；表格按行续页并重复表头，代码按行续页，图片与图注保持完整。

03 / 技术内容

宽表与长公式可单独调整

表格字号、公式缩放、代码字号不影响普通正文。H2、H3、H4 各自拥有页尾安全区，避免标题卡在页面底部。

04 / 首卡规则

文章名不必重复出现

手动文章名优先，其次取首个 H1，再取文件名。首个 H1 用于首卡或封面，不会在正文再渲染一次；后续 H1 仍是新章节。

05 / 导出校验

导出前先阻止不完整成品

字体、图片解码、Markdown 警告与卡片边界会在导出前检查。预览与 PNG 共用同一份分页结果，不存在两套排版。

所有内容只在本地浏览器处理。 GitHub Pages 只分发静态网页；草稿、图片绑定与 PNG ZIP 都保留在你的设备上。

PRACTICAL NOTES

开始前，了解这几件事就够了

为什么单独导入 .md 后还要选择图片所在文件夹？

浏览器不能获得电脑上该文件的父目录权限。这是安全限制。选择一次文章根目录或 assets 后，应用才能按 Markdown 的路径补齐实际图片；它不会上传或导入无关文件。

长公式或超宽表格显示拥挤怎么办？

先在“技术块”中减小公式缩放或表格字号；仍然拥挤时，将公式改为多行或精简表格列。技术内容更多时可改用 2:3 技术长图。

哪些浏览器最适合导出？

推荐最新版桌面 Chrome 或 Edge。手机可编辑和预览，但高清长文导出受设备内存影响更大；远程图片需要图片来源允许浏览器读取，才能稳定导出。
